updated: 2026-07-17T12:59

- (direction by user) Implement the basic visualization slice by parsing generated TTK result CSV files and rendering a table in a webview.
- (direction by user) Add a required Mode column that identifies kernel, aclnn, or e2e; retain a Test file column to distinguish multiple CSV inputs in one mode.
- (note) GitCode issue 45 requires testcase_name, dyn_precision, cst_precision, bin_precision, and precision_status, aggregate reporting across selected modes, and identification of failed testcases.
- (decision) This slice supersedes only the prior deferral of a results webview; the completed basic TTK runner remains unchanged as the execution baseline and the slice does not claim full GC-45 closure.
- (capability) CAP-1 intent: ingest every result CSV produced by a completed ST run into a typed report; success: valid files yield rows with all five required fields and malformed files remain inspectable but make the report non-passing.
- (capability) CAP-2 intent: show a run summary and testcase table inside the IDE; success: the panel displays total, passed, failed, and invalid counts plus Mode, Test file, Testcase, Dyn precision, CST precision, Bin precision, and Status columns.
- (capability) CAP-3 intent: combine results from every selected mode and input CSV without losing provenance; success: each row carries mode and source artifact identity and duplicate testcase names from different files remain distinct.
- (capability) CAP-4 intent: let the user inspect the authoritative raw artifact; success: an Open CSV action resolves an extension-owned artifact ID and opens only the corresponding produced file.
- (constraint) Filesystem access and CSV parsing stay in the extension host; the webview receives only structured-cloneable DTOs with relative display paths and never reads arbitrary paths.
- (constraint) The parser accepts UTF-8 CSV with BOM, quoted commas, quoted newlines, CRLF or LF, reordered required headers, and extra columns; missing headers, invalid UTF-8, unreadable files, empty results, missing testcase/status values, or unknown statuses are explicit invalid evidence.
- (decision) Mode provenance comes from the executed plan, never filename inference; Test file and Result file labels are workspace-relative while absolute paths remain extension-private.
- (constraint) Overall status is PASS only when every artifact parses, at least one testcase exists, and every precision_status is PASS; any explicit FAIL prevents PASS, and missing, unknown, or malformed evidence yields INVALID.
- (constraint) The panel uses bundled local assets only, strict webview resource policy, escaped Vue rendering, validated message actions, VS Code theme support including high contrast, and English plus Chinese localization.
- (decision) A dedicated reusable ST results panel replaces its in-memory report and reveals itself after each successful TTK process sequence; run history and restoration after extension restart are deferred.
- (decision) Keep the existing relative-path completion notification and raw-file fallback so a panel rendering failure does not hide produced artifacts.
- (assumption) precision_status is normalized case-insensitively after trimming; only PASS and FAIL are recognized for the MVP and every other value is shown raw as invalid evidence.
- (note) Implementation uses a shared report DTO, a strict extension-side result parser/report builder, a dedicated panel with a ready-aware typed connector, and a Vue Ant Design table with pagination and mode/status filters.
- (non-goal) Exclude pre-run testcase-row selection, IntelliJ-style test tree, persisted run history, cross-run comparison, export formats, rerun controls, and remote telemetry from this MVP.
- (note) Verification covers parser and aggregation unit tests, provenance through ST orchestration, panel lifecycle and artifact-ID authorization, web type-check/build, localized light/dark/high-contrast manual checks, and packaged VSIX asset inspection.
- (decision) When invalid evidence and explicit FAIL coexist, overall INVALID takes precedence while failed testcase counts remain visible.
- (decision) Initial safety bounds are 16 MiB per result file and 20000 aggregate testcase rows; exceeding either makes the report invalid and preserves raw CSV access rather than silently truncating.
- (decision) A structurally malformed CSV contributes no parsed rows; row-local missing required values contribute explicit invalid rows, and both retain the raw artifact action.
- (constraint) File-level parser failures cross into the webview as stable error codes plus safe details, not pre-localized messages or absolute paths.
- (event) Self-validation pass 1 coherence: PASS; four stable capabilities each have intent and testable success, constraints bend implementation, non-goals are explicit, and no unresolved placeholder remains.
- (event) Self-validation pass 2 preservation: PASS; the basic webview table, all five issue fields, aggregate status, mode and test-file provenance, raw CSV action, offline-safe UI, failure semantics, and verification requirements are preserved; wrapper-only content dropped: none.
- (event) Spec finalized for implementation with SPEC.md, implementation.md, architecture-diagrams.md, and adopted baseline/project companions.
